# 问题环境写作逻辑

## 1. 约束优化

核心区分：**feasibility** 与 **objective quality**。

必须写清：

- 约束类型、数量和难度；
- 约束违反如何度量；
- 可行解与不可行解如何比较；
- penalty、repair、可行性规则、多目标化或专门算子的假设；
- 算法成本是否包含修复/惩罚计算；
- 结果中可行率和约束违反，而不只是目标值。

常见风险：把惩罚系数调好后的结果写成方法普遍有效；不报告不同可行域比例。

## 2. 动态优化

核心是跟踪变化，而不是一次收敛。

必须写清：

- 什么随时间变化：目标、约束、约束边界、数据分布、环境参数；
- 变化频率、幅度、可预测性；
- 算法是否知道变化发生；
- 记忆、重启、预测、多样性保持或迁移策略；
- 评价是在变化前、变化后还是整个时间线上；
- 时间预算与评价预算如何定义。

常见风险：用静态 benchmark 上的一次收敛结果声称 dynamic optimization。

## 3. 噪声、不确定与鲁棒

先区分：

- fitness noise；
- decision-variable perturbation；
- environmental uncertainty；
- model approximation error；
- robust solution vs stochastic performance。

写作要求：

- 噪声/不确定性分布和强度；
- 重采样或置信度策略；
- 鲁棒性评价标准；
- 最坏情况、均值、方差或风险指标；
- 额外评价成本。

避免把“随机算法运行结果有波动”称为鲁棒性研究。

## 4. 昂贵优化 / Surrogate-assisted EC

核心矛盾是：降低真实评价次数，同时控制模型误差和模型管理成本。

必须写清：

- 每次真实评价的单位和成本；
- 可承担的总真实评价预算；
- surrogate 类型、训练数据和更新频率；
- 何时相信模型、何时真实评价；
- 模型误差如何影响选择；
- 模型训练/推理开销；
- 与相同真实评价预算的基线比较。

常见风险：只报告迭代速度，忽略昂贵评价；或只报告 FEs，忽略 Kriging/神经网络训练成本。

## 5. 大规模优化

核心是可扩展性和变量结构。

必须写清：

- 维度范围及选择理由；
- 变量是否可分解、重叠、交互；
- 分组、降维或直接搜索的机制；
- 随维度增长的 FEs、时间和内存；
- 分组/学习成本是否计入；
- 是否只验证 separable 或 sparse 问题。

`scalable` 必须绑定维度和预算范围。

## 6. 多峰优化

目标是找到多个有质量的峰，而非只找到全局最优。

必须写清：

- 要保留决策空间多个解，还是目标空间多个 trade-off；
- niching/speciation 机制；
- peak accuracy、peak ratio、diversity 等指标；
- 已知峰数量未知时如何评价；
- 避免重复解和维持局部精细搜索的策略。

## 7. 多任务/迁移优化

必须写清：

- source/target task 如何定义；
- 相似性如何度量或假设；
- 迁移什么知识：解、映射、模型、参数、子空间；
- 何时迁移、迁移多少、如何防止负迁移；
- 迁移成本是否少于从头搜索。

## 8. 组合优化

必须写清：

- 编码是否天然可行；
- 不可行解如何修复；
- 邻域结构和问题知识；
- 领域基线；
- 实例规模和结构；
- 结果是否只对某类实例有效。

不要把连续算子直接套到排列问题而不解释合法性。
